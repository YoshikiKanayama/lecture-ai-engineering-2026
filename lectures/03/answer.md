## 宿題

- 取り組んだレベル：発展（a）ADK で作り直す
- やったこと：
  - `adk_agent/glossary_agent/agent.py` と `__init__.py` を作り、演習と同じ `INSTRUCTIONS` とツール3つ（`search_glossary`・`get_lecture_summary`・`make_quiz`）を ADK の `Agent` に渡した。`app/` のファイルは変えていない
  - モデルは文字列で書かず、`app.config.MODEL` を使った。Pydantic AI 版と同じモデルになり、`AIE_MODEL` での切り替えも同じように効くため
  - Codespaces で `PYTHONPATH=. uv run --with google-adk adk run adk_agent/glossary_agent` を実行し（google-adk 2.14.0）、演習と同じ3つの質問を入力した
- 結果：
  - 書き方の比較

    | 観点 | Pydantic AI（`app/agent.py`） | ADK（`adk_agent/glossary_agent/agent.py`） |
    |---|---|---|
    | 指示の渡し方 | `Agent(instructions=INSTRUCTIONS)` | `Agent(instruction=INSTRUCTIONS)`（名前が単数形） |
    | ツールの渡し方 | 作ったあとに `agent.tool_plain(関数)` で1つずつ登録 | 作るときに `tools=[関数, ...]` でまとめて渡す |
    | モデル | 実行時に `run_sync(..., model=...)` で渡す（テストで `TestModel` に差し替えるため） | 作るときに `model=` で固定 |
    | 名前 | 不要 | `name=` が必須。変数名も `root_agent` に決まっている（`adk run` がこの名前で探す） |
    | 動かし方 | 自分で書いた CLI（argparse） | ADK 付属の `adk run`（対話）。CLI を書かずに済む |
    | ツール呼び出しの確認 | `--trace` で `result.all_messages()` から表示（自分で書いた機能） | `adk run` の画面には出ない。ログ（`/tmp/agents_log/`）か Web UI で見る |

    どちらも、ツールは関数の名前・型ヒント・docstring から説明が作られるので、`app/tools.py` の関数をそのまま渡すだけで使えた

- 気づき・疑問：
  - 回答の中身はほぼ同じだった。同じモデル・同じ指示・同じツールなので、ふるまいを決めているのはフレームワークではなく、指示とツールの説明文だと分かった。フレームワークが変えるのは、組み立て方と、動かし方だと感じた
  - 確認問題の用語が違ったのは、`make_quiz` が `random.choice` で選んでいるためで、フレームワークの違いではない
  - ADK 版の確認問題では、`INSTRUCTIONS` の「回答の最後に、関係する回（第N回）を示す」が守られなかった。各1回しか試していないので、ADK だから守られないのか、たまたまかは分からない。複数回聞いて比べる必要がある
  - `adk run` ではツールが呼ばれたかが画面に出ないので、「3レベル」の回答が用語集の定義とほぼ同じ文面であることから、検索したと推測するしかなかった。Pydantic AI 版は `--trace` を自分で書いてあるので確かめられる。エージェントでは「どのツールがどの引数で呼ばれたか」を見られることが大事で、ADK を使うならログや Web UI で確かめる手順をセットで持っておくべきだと思った
